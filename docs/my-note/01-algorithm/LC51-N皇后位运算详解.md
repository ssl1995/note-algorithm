# LC51 N皇后：位运算解法详解
## 一、题目回顾
按照国际象棋的规则，皇后可以攻击与之处在**同一行、同一列、同一斜线**上的棋子。n 皇后问题研究的是如何将 n 个皇后放置在 n×n 的棋盘上，并且使皇后彼此之间不能相互攻击。返回所有不同的解决方案。
```
输入：n = 4
输出：[[".Q..","...Q","Q...","..Q."],
       ["..Q.","Q...","...Q",".Q.."]]
```
## 二、核心思想
### 1. 每行恰好放一个皇后
n 个皇后放在 n×n 棋盘上且互不攻击，必然**每行恰好一个皇后**。所以可以按行做 DFS：第 `row` 行选一个合法的列放皇后，然后递归下一行。
普通回溯做法需要用 3 个 `Set`（列、主对角线、副对角线）来判断某个位置能否放皇后。**位运算解法用 3 个整数的二进制位代替这 3 个集合**，把"判断 + 选位 + 更新状态"全部变成 O(1) 的位操作，速度和空间都远优于 Set。
### 2. 用整数的二进制位表示棋盘状态
以 n = 4 为例，棋盘的 4 列用二进制的低 4 位表示：
```
二进制位:   3 2 1 0        ← 位编号
对应列:    3 2 1 0        ← 棋盘列下标
           ↑     ↑
        bit i = 1 表示第 i 列"已被占用/受攻击"
```
例如 `col = 0101`（十进制 5）表示第 0 列和第 2 列已经放了皇后。
## 三、dfs 参数签名详解
```java
private void dfs(char[][] board, int row, int col, int left, int right,
                 int limit, List<List<String>> res)
```
| 参数 | 含义 | 举例（n=4） |
|------|------|------------|
| `board` | 棋盘，仅用于最后构造输出字符串 | `char[n][n]`，初始全为 `'.'` |
| `row` | 当前正在放第几行的皇后（递归层数） | 0 ~ n-1 |
| `col` | **列约束**：之前所有皇后占用的列。bit=1 表示该列不可用 | `0101` = 第0、2列被占 |
| `left` | **左斜线（↙ 方向）约束**：之前皇后在左斜线上对当前行造成的攻击位。bit=1 表示不可用 | 见下方推演 |
| `right` | **右斜线（↘ 方向）约束**：之前皇后在右斜线上对当前行造成的攻击位。bit=1 表示不可用 | 见下方推演 |
| `limit` | 掩码，固定值 `(1 << n) - 1`，即低 n 位全 1。**作用：把"可用位"限制在 n 列范围内**，屏蔽移位产生的高位垃圾 | n=4 时 `limit = 1111` |
| `res` | 结果收集器 | — |
### 为什么 left 右移、right 左移？
关键在递归调用这一行：
```java
dfs(board, row + 1, col | place, (left | place) >> 1, (right | place) << 1, limit, res);
```
假设当前行在 bit i 放了皇后（`place = 1 << i`），看它对**下一行**的影响：
- **同列**：下一行的 bit i 仍被占 → `col | place`（位置不变，直接传递）
- **左斜线 ↙**：往下一行走，攻击位列号减 1，即向**低位**移动一格 → 整体**右移** 1 位：`(left | place) >> 1`
- **右斜线 ↘**：往下一行走，攻击位列号加 1，即向**高位**移动一格 → 整体**左移** 1 位：`(right | place) << 1`
```
当前行:      . Q . .        place = 0010 (bit 1，即第 1 列)
              ↙ ↓ ↘
下一行:     列0 列1 列2
攻击位:  left=0001  col=0010  right=0100
```
> 记忆口诀：**左斜右移（`>>`），右斜左移（`<<`）**。↙ 方向列号递减对应二进制右移，↘ 方向列号递增对应左移。
## 四、核心位运算四板斧
每进入一个 `dfs` 层，逻辑固定为四步：
```java
if (col == limit) {            // ① 终止条件：所有列都放了皇后 → n 个皇后放完
    addRes(board, res);
    return;
}
int ban = col | left | right;  // ② 三类约束取并集：bit=1 表示不可用
int can = limit & (~ban);      // ③ 取反求可用位，并用 limit 砍掉高位，bit=1 表示可放
while (can != 0) {
    int place = can & -can;    // ④ 取出最低位的 1，作为本行放皇后的位置
    can ^= place;              //    从候选集中删掉该位（保证每个候选都试一遍）
    ...
    dfs(board, row + 1, col | place, (left | place) >> 1, (right | place) << 1, limit, res);
    ...
}
```
| 技巧 | 代码 | 说明 |
|------|------|------|
| 合并约束 | `col \| left \| right` | 任意一类攻击到就不可用 |
| 求候选位 | `limit & (~ban)` | `~ban` 在 Java 中会带出高位 1，必须用 `limit` 掩码截断 |
| 取最低位的 1 | `can & -can` | 如 `0110 → 0010`，等价于 `can & (~can + 1)` |
| 清除最低位的 1 | `can ^= place` | 等价于 `can & (can - 1)` |
### 终止条件为什么是 `col == limit`？
每放一个皇后，`col` 就多一个 1。放满 n 个皇后时 `col` 的低 n 位全为 1，即 `col == limit`。此时说明 n 行都放好了，收集答案。这比判断 `row == n` 更贴合位运算风格（两者等价）。
## 五、完整示例推演（n = 4）
`limit = 1111`，逐层跟踪 `(row, col, left, right)` 与候选位 `can`（**bit i 对应第 i 列**）。
### 失败分支：第 0 行先试第 0 列
- **第 0 行**：`col=0000, left=0000, right=0000` → `ban=0000`，`can=1111`，取最低位 `place=0001`（第 0 列），递归：`col=0001, left=(0|0001)>>1=0000, right=(0|0001)<<1=0010`
- **第 1 行**：`ban = 0001|0000|0010 = 0011`，`can = 1100`。先取 `place=0100`（第 2 列）：
  - 递归得 `col=0101, left=(0|0100)>>1=0010, right=(0010|0100)<<1=1100`
  - **第 2 行**：`ban = 0101|0010|1100 = 1111`，`can = 0000` → **死路，while 不执行，直接回溯** ✗
- 回到第 1 行改取 `place=1000`（第 3 列）：递归得 `col=1001, left=(0|1000)>>1=0100, right=(0010|1000)<<1=10100`（溢出到第 4 位，不影响，后面会被 `limit` 掩码屏蔽）
  - **第 2 行**：`ban = 1001|0100|10100 = 11101`，`can = 1111 & ~ban = 0010`，取 `place=0010`（第 1 列），递归得 `col=1011, left=(0100|0010)>>1=0011, right=(10100|0010)<<1=101100`
  - **第 3 行**：`ban` 低 4 位 = `1011|0011|1100 = 1111`，`can = 0000` → **死路** ✗
- 第 0 行的 `place=0001` 整枝失败，回溯改取 `place=0010`（第 1 列）
### 成功分支：逐层位运算轨迹
| 行 | col（入参） | left（入参） | right（入参） | ban = col\|left\|right | can = limit & ~ban | place（取最低1） | 本行放置 |
|----|------|------|------|------|------|------|------|
| 0 | 0000 | 0000 | 0000 | 0000 | 1111 | **0010**（列1） | `.Q..` |
| 1 | 0010 | 0001 | 0100 | 0111 | 1000 | **1000**（列3） | `...Q` |
| 2 | 1010 | 0100 | 11000* | 11110 | 0001 | **0001**（列0） | `Q...` |
| 3 | 1011 | 0010 | 110010* | …1011（低4位） | 0100 | **0100**（列2） | `..Q.` |
\* 左移可能溢出到第 n 位及更高位，不影响正确性——`can = limit & ~ban` 中的 `limit` 掩码会把高位全部屏蔽掉，这也是 `limit` 存在的意义之一。
第 3 行递归后 `col = 1011 | 0100 = 1111 == limit`，命中终止条件，收集第一个解：
```
.Q..
...Q
Q...
..Q.
```
整棵搜索树中所有 `can == 0` 的分支被位运算瞬间剪掉，最终收集到 2 个解（另一个是上面解的镜像：列序 2,0,3,1）。
## 六、棋盘输出与回溯
`board` 只在两个地方被碰：
```java
board[row][colIdx] = 'Q';   // 放皇后（colIdx 由 place 的位号算出）
dfs(...);                    // 递归
board[row][colIdx] = '.';   // 撤销：回溯恢复现场
```
`getLastOneIndex(place)` 求 `place`（只有一个 1）中这个 1 的位号，即列下标：
```java
private int getLastOneIndex(int num) {
    // 一行替代：return Integer.numberOfTrailingZeros(num);
    int index = 0;
    for (int i = num; (i & 1) == 0; i >>= 1) index++;
    return index;
}
```
## 七、复杂度分析
| 维度 | 复杂度 | 说明 |
|------|--------|------|
| 时间 | O(n!) 实际远小于 | 位运算让每层的合法性判断从 O(1)~O(n) 的 Set 操作变成纯寄存器操作，常数极小；剪枝把无效分支全部过滤 |
| 空间 | O(n) | 递归深度 n，每行状态只用 3 个 int，不需要任何 Set |
相比普通回溯（Set 判断），位运算版在 n ≤ 15 内速度通常快 3~10 倍，是 N 皇后系列（LC51 求方案、LC52 求数量）的最优写法。
## 八、记忆口诀
> **三数记列斜，一掩卡边界；**
> **或出禁，反与候选；**
> **负与取一，异或删一；**
> **列满收答案，左斜右移、右斜左移。**

逐句对应代码：
| 口诀 | 对应代码 |
|------|----------|
| 三数记列斜 | `col`、`left`、`right` 三个 int 记列、↙、↘ 约束，bit=1 被攻击 |
| 一掩卡边界 | `limit = (1<<n)-1`，把可用位卡在低 n 位 |
| 或出禁 | `ban = col \| left \| right` |
| 反与候选 | `can = limit & (~ban)`，bit=1 可放 |
| 负与取一 | `place = can & -can`，取最低位 1 |
| 异或删一 | `can ^= place`，删掉已试位置 |
| 列满收答案 | `col == limit` 时 `addRes` |
| 左斜右移、右斜左移 | `(left\|place)>>1`、`(right\|place)<<1`，`col\|place` 原样下传 |
## 九、要点总结
1. **三个整数代替三个集合**：`col`（列）、`left`（↙ 斜）、`right`（↘ 斜），bit=1 表示被攻击。
2. **斜线传播靠移位**：进入下一行时，`left` 右移 1 位、`right` 左移 1 位，列约束 `col` 原样传递。
3. **`limit` 掩码不可少**：Java 的 `~` 会把高位全部置 1，必须 `limit & ~ban` 把候选位限制在低 n 位。
4. **候选枚举套路固定**：`can & -can` 取一个候选 → `can ^= place` 删除 → 递归 → 回溯。
5. **终止条件**：`col == limit`（所有列放满），等价于 `row == n`。
