# Agent 面试题 01：什么是 Agent？与大模型有什么本质不同？
> 来源：https://xiaolinnote.com/ai/agent/1_whatisagent.html
## 🎯 核心考点一句话
答好这道题的关键是抓住核心词：**「自主闭环」**——Agent 能自主规划、多步执行、感知结果再调整。
## 💡 简要回答（面试可直接背）
Agent 本质上是一个**能自主完成目标的 AI 系统**，跟传统 AI 最核心的区别在于「自主性」和「能行动」。
传统 AI 是被动响应（问一个答一个，每次独立）；而 Agent 有自己的规划能力：给它一个复杂目标，它会自己拆成多步，通过调工具、访问记忆、感知环境一步步执行直到完成。它不只是输出文字，而是真的能做事。
## 📝 详细解析
### 普通大模型的三大局限（一环扣一环）
1. **知识被冻结**：训练数据有截止日期，无法获取实时信息（今天天气、最新股价都不知道）；
2. **不能行动**：本质是文本生成器，只能告诉你「怎么做」，没法真正执行（能写邮件正文，但点不了发送按钮）；
3. **没有持续状态**：每次调用之间完全失忆，不记得上一轮内容，更无法跨任务记住用户偏好。
三者叠加 → 普通 LLM 只能做「一问一答」，多步骤协作任务完全无能为力。
### Agent 特别在哪？核心运作闭环
**感知 → 规划 → 行动 → 再感知**。
给它目标（如「调研竞品整理成报告」），它先拆解任务，再逐步执行，每步结果反馈回来指导下一步。
支撑这个闭环的三件核心事：
**1. 工具调用（Tool Use）——从「说话」变「做事」**
- Agent 能调用搜索引擎、代码执行器、数据库、API 等外部工具；
- ⚠️ 易误解点：**不是模型自己执行**，模型只负责决策「调什么、参数是什么」，真正执行的是你的代码，结果再反馈给模型。**模型是大脑，不是手脚**（决策与执行分离）；
- 价值：一举突破三大局限（接搜索引擎→实时信息；接邮件 API/代码执行器→真正做事）。
工具定义示例（本质是一份「技能说明书」，无执行逻辑）：
```python
tools = [
    {
        "name": "get_weather",
        "description": "获取指定城市的当前天气",
        "parameters": {
            "type": "object",
            "properties": {"city": {"type": "string", "description": "城市名称"}},
            "required": ["city"]
        }
    },
    {
        "name": "send_email",
        "description": "发送邮件给指定收件人",
        "parameters": {
            "type": "object",
            "properties": {
                "to": {"type": "string"},
                "subject": {"type": "string"},
                "body": {"type": "string"}
            },
            "required": ["to", "subject", "body"]
        }
    }
]
# 任务："帮我查一下北京天气，然后发邮件给 boss@company.com"
# Agent 分两步真实执行：
# 第一步：调用 get_weather(city="北京") → 得到 "晴天 15°C"
# 第二步：调用 send_email(to="boss@company.com", subject="今日天气", body="北京今天晴天 15°C")
```
**2. 记忆机制——让 Agent 能「记事」**
- **短期记忆**：当前任务执行中的中间状态（存在上下文里），保证做到一半不忘前面发生了什么；
- **长期记忆**：跨任务的用户偏好、历史操作记录，通常用**向量数据库**存储 + 语义检索召回；
- 两层记忆保证复杂任务执行的连贯性。
**3. 多步推理和自我纠错——Agent 最像「人」的地方**
- 某步失败不会崩掉，而是感知失败、分析原因、换方式重试（换关键词再搜、看报错调参数重调）；
- 能回头审视：这步对不对？结果符合预期吗？要不要调整后续计划？
- 这是 Agent 区别于**简单自动化脚本**的关键：碰障碍会绕路，而不是一条路走到黑。
### 本质区别总结
普通 LLM「帮我发天气播报邮件」→ 只告诉你怎么写代码；Agent → 真的去调天气 API、拿数据、组织内容、调邮件接口，全程自动完成。**从生成文字，到执行任务**。
## 🔥 延伸考点：为什么 Agent 现在才爆发？（2024-2025）
三个条件同时成熟：
1. **大模型能力跨过「能用」门槛**：GPT-4、Claude 3 这一代推理和指令遵循能力质变，能真正做多步决策；
2. **工具调用标准化**：OpenAI 2023 年推出 Function Calling（结构化 JSON 输出调用请求），各厂商跟进，接工具的工程成本大幅降低；
3. **配套生态完善**：LangChain、LlamaIndex 降低开发门槛；向量数据库解决长期记忆；API 服务日益丰富。
## 🔥 延伸考点：两大标准协议（面试高频加分项）
### MCP（Model Context Protocol，模型上下文协议）
- Anthropic 2024 年底提出，Agent 工具世界的「USB-C 接口」；
- 解决的问题：M 个框架 × N 个工具 = M×N 套适配代码 → MCP 用标准 JSON-RPC 协议统一，工具方暴露为 MCP Server，Agent 通过内置 MCP Client 即可发现调用；
- 架构三层：**Host**（用户交互的 AI 应用，如 Claude Desktop、Cursor）→ **Client**（管理通信）→ **Server**（暴露工具能力）；
- 2025 年 12 月捐给 Linux 基金会旗下 Agentic AI Foundation（AAIF），已有数千个公开 MCP Server。
### A2A（Agent2Agent，Agent 间通信协议）
- Google 2025 年 4 月推出，解决「Agent 怎么和另一个 Agent 协作」；
- 核心设计：**Agent Card（名片）**——写明能做什么、正在做什么、需要什么输入，其他 Agent 读名片即知如何协作；
- 2025 年 6 月捐给 Linux 基金会，SAP、Salesforce、ServiceNow 等大厂接入。
### MCP vs A2A 的关系（互补，各管一层）
- **MCP 管 Agent 与工具的连接**（让每个 Agent 方便地「伸手拿工具」）；
- **A2A 管 Agent 与 Agent 的通信**（让不同 Agent 方便地「互相说话合作」）；
- 未来格局：两个协议同时存在、各管一层。
## ⚠️ 面试常见踩雷点（三个典型误区）
1. **把 Agent 等同于「插件」或「工具调用」**：工具调用只是 Agent 能力的一部分，不是 Agent 本身；
2. **停在「能调工具」层面，没点出自主性**：关键不是「有工具」，而是「自己决定用不用、什么时候用、用哪个」；
3. **忽略执行闭环**：「感知 → 规划 → 行动 → 再感知」的循环才是区别于普通 LLM 的核心机制。
## ✅ 答题 checklist
- [ ] 点出自主规划能力：给复杂目标能自己拆成多步；
- [ ] 点出能行动：通过工具调用与外部世界真实交互；
- [ ] 点出闭环：每步结果反馈回来指导下一步，不是一次性生成完就结束；
- [ ] 加分项：模型只是「大脑」，工具真正执行的是代码，模型只负责决策（决策与执行分离）；
- [ ] 加分项：能讲清 MCP 与 A2A 两个协议的定位和区别。
