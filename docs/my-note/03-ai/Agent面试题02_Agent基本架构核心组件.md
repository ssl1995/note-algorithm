# Agent 面试题 02：Agent 的基本架构由哪些核心组件构成？
> 来源：https://xiaolinnote.com/ai/agent/2_components.html
## 🎯 核心考点一句话
Agent 四大核心组件：**LLM（大脑）、工具系统（手脚）、记忆系统（状态）、规划模块（拆解）**，缺一不可。
## 💡 简要回答（面试可直接背）
Agent 的基本架构有四个核心组件：LLM、工具、记忆、规划模块。
- **LLM** 是整个系统的大脑，负责理解任务和做决策；
- **工具**让 Agent 能跟外部世界交互（搜索、执行代码、调 API）；
- **记忆**让 Agent 在任务执行过程中保持状态，不会「失忆」；
- **规划模块**负责把复杂目标拆解成可执行的步骤。
四个组合在一起，才让 Agent 具备自主完成任务的能力。
公司类比（面试加分）：**LLM 是老板**（拍板决策）、**工具系统是外包执行团队**（真正干活）、**记忆系统是档案室**（存档调档）、**规划模块是项目经理**（把大目标拆成任务单）。
## 📝 详细解析
### 组件一：LLM 核心（大脑）
- 所有输入（用户指令、工具返回、记忆内容）最终都经 LLM 理解决策：下一步是继续思考、调工具、还是给最终答案；
- **System Prompt 是容易被忽略的重点**：相当于给老板的「岗位说明书」，定义角色、行为边界、输出格式，决定 Agent 的「人格」；工程实践中 System Prompt 调优占开发时间相当大比例，是最直接控制 Agent 行为的手段。
**模型选型考点**（不是越贵越好，按任务复杂度/延迟/成本权衡）：
1. **推理能力**：Agent 需要多步决策，GPT-4o、Claude Sonnet 比小模型强但贵；趋势是用推理模型（o1/o3、DeepSeek-R1 等 Reasoning Model）做 Agent 大脑，代价是延迟高、token 消耗大；
2. 常见工程做法：**大模型做核心决策（任务规划、关键判断），小模型做简单任务（意图分类、格式提取）**；
3. **工具调用稳定性**：有的模型生成 JSON 常出错、参数乱填，导致生产环境大量重试和 token 浪费；
4. **上下文窗口大小**：复杂任务十几步下来容易撑满，窗口太小后面步骤「看不到」前面的历史。
### 组件二：工具系统（与外部世界交互的唯一入口）
- LLM 是纯「语言处理器」，不能上网/读文件/执行代码，这些限制都靠工具突破；任何能用函数封装的能力都可变成工具；
- 核心分工：**模型负责「决定做什么」，程序负责「真正执行」**（决策与执行分离）。
工具定义标准格式（OpenAI function calling）：
```python
# 只需告诉模型三件事：工具名、能做什么、需要哪些参数
tools = [
    {
        "type": "function",
        "function": {
            "name": "search_web",
            "description": "搜索互联网上的信息",
            "parameters": {
                "type": "object",
                "properties": {
                    "query": {"type": "string", "description": "搜索关键词"}
                },
                "required": ["query"]
            }
        }
    }
]
# LLM 决定调用时返回：{"tool_call": {"name": "search_web", "arguments": {"query": "2024年大模型最新进展"}}}
# 你的代码真正执行搜索，把结果再塞回给 LLM
```
- ⚠️ 易忽略考点：**工具描述（description）的质量直接影响 Agent 表现**。模型靠 description 判断「什么时候该用」；描述含糊会导致误调/漏调（如只写「查询数据」，用户问天气也可能去查库）。工具描述需要反复调优，重要性不亚于 prompt 工程。
**工具标准化：MCP 协议**
- Anthropic 2024 年底提出，底层基于 JSON-RPC；不只标准化工具，还定义三类能力：**Tools**（改变外部世界的操作，如发邮件）、**Resources**（只读数据源，如文件内容）、**Prompts**（预定义提示词模板）；
- 架构三层：**Host**（用户交互的 AI 应用）→ **Client**（管理连接）→ **Server**（暴露能力）；
- 「工具世界的 USB-C 接口」：Server 按标准实现一次，任何支持 MCP 的 Agent 自动发现调用；
- 2025 年 12 月捐给 Linux 基金会 Agentic AI Foundation，已有数千个公开 MCP Server。
### 组件三：记忆系统（分两层，机制和用途完全不同）
**短期记忆**：当前任务的上下文，装在 context window 里，存中间状态（每步搜索/执行结果）。类比人的「工作记忆」：容量有限，任务结束即清空。
**长期记忆**：通常用**向量数据库**实现，重要信息 embedding 后存储，用时做语义检索召回。类比人的「长期记忆」：容量大、可跨天保留，但需主动「回忆」。
长期记忆可借用认知科学分类理解（实际实现多为向量检索 + metadata 过滤，不一定真分这么细）：
- **语义记忆**：事实性知识（「用户是金融行业的」「某 API 限频每分钟 60 次」）；
- **情景记忆**：具体经历（「上次退款问题查了订单系统，订单已过退款期」）；
- **程序性记忆**：「怎么做事」的方法论沉淀（「退款标准流程：先查订单状态再核实支付方式」），让 Agent 下次直接套用高效流程。
**记忆系统的工程挑战（高频追问点）**：
1. **上下文窗口有限**：复杂任务十几步就撑满 → 方案：摘要压缩（浓缩前序步骤）或滑动窗口（只保留最近几步），都会丢信息，核心是「记住够多」与「不撑爆上下文」的取舍；
2. **长期记忆存什么**：全塞进去检索噪音大，存太少失去意义 → 存入前做**重要性评估**，只持久化有价值信息；
3. **记忆衰减（Memory Decay）**：给每条记忆加时间权重，越久远权重越低。相关性分数 = 语义相似度 × 时间衰减因子（指数衰减）；衰减速度按场景调整——客服场景衰减快（对话多为一次性），法律合规场景衰减慢（历史记录长期被引用）。
### 组件四：规划模块（决定能否应对复杂任务）
把复杂目标拆解成步骤：「写竞品分析报告」→ 搜索资料 → 整理数据 → 对比分析 → 撰写报告。
**底层依赖的推理技术**：
- **CoT（Chain of Thought，思维链）**：让模型把思考过程写出来（如 prompt 加「Let's think step by step」）。原理：token 逐步生成，中间步骤输出成为下一步输入，等于给模型更多「思考空间」；
- **ToT（Tree of Thoughts，思维树）**：每个推理节点展开多个分支、评估质量、选最优路径继续。CoT 是「一条路走到底」，ToT 是「岔路口先看几条路选最好的」。适合创造性/复杂决策场景，但计算成本更高。
**两种主流规划模式**：
1. **Plan-and-Execute（先规划后执行）**：先输出完整步骤列表再顺序执行。优点：结构清晰、可人工审核；缺点：中间步骤结果偏离预期时原计划失效，需重新调整；
2. **ReAct（边执行边规划）**：每走一步根据结果重新思考下一步。优点：灵活、随时调整；缺点：每步是局部最优决策，容易「走偏」忽略整体目标；
3. 工程实践常**两者结合**：先粗计划定大方向，执行中根据反馈动态微调。
### 四组件协作全景（伪代码）
```python
# Agent 运行的核心 loop（伪代码）
def agent_run(user_goal: str):
    # 第一步：规划模块上场，把目标拆成步骤列表
    plan = llm.plan(user_goal)
    memory = []  # 短期记忆，存每步中间结果
    for step in plan:
        # 第二步：LLM 核心做决策
        action = llm.decide(
            step=step,
            history=memory,                    # 传入短期记忆
            long_term=vector_db.search(step)   # 长期记忆检索相关历史
        )
        if action.type == "tool_call":
            # 第三步：工具系统真正执行
            result = tools.execute(action.tool_name, action.args)
            memory.append({"step": step, "result": result})  # 结果存入短期记忆
        elif action.type == "final_answer":
            return action.content  # 任务完成，返回最终答案
```
核心节奏：**规划 → 决策 → 执行 → 结果存入记忆 → 再决策**，循环往复直到完成。
LangChain、LlamaIndex、AutoGen 等主流框架本质都是围绕这四组件设计，只是封装方式和侧重点不同。
## ⚠️ 面试常见踩雷点（三个典型误区）
1. **漏掉组件**：只说 LLM 和工具两个，忘了记忆和规划——这两个恰恰是让 Agent 能跑复杂任务的关键；
2. **对记忆理解太浅**：「记忆就是上下文」不完整。正确说法：短期记忆放 context window（当前任务中间状态），长期记忆用向量数据库（跨任务的用户偏好和历史），两者机制和用途完全不同；
3. **工具分工理解偏差**：模型本身不执行工具，只输出「调哪个、传什么参数」的决策，真正执行的是代码——「决策和执行分离」是很容易被追问的点。
