# Agent 面试题 15：讲讲 Agent 的反思机制？为什么要用反思？具体怎么实现？
> 来源：https://xiaolinnote.com/ai/agent/15_reflection.html
## 🎯 核心考点一句话
反思机制是一个**「生成 → 评估 → 改进」的结构化闭环**，而不是「不满意就随机重试」——最大的设计难点在「评估」这一步（要给明确检查维度 + PASS 出口），工程上最重要的是**硬性最大轮次防死循环**。
## 💡 简要回答（面试可直接背）
- 反思机制：Agent 在完成一个步骤或整个任务后**自我评估输出质量**，不达标就结合评估意见定向改进，而不是从头随机重生成；
- 为什么要用：LLM 是「一口气」生成的，第一次输出不一定最优（逻辑跳跃、遗漏细节、事实错误、表达含糊），加一轮自我检查能显著提升质量；
- 代价是每轮多至少一次 LLM 调用，token 和延迟都增加，所以**只在质量要求高的关键节点启用，不是每步都做**。
## 📝 详细解析
### 核心循环：生成 → 评估 → 改进
- 思路来自 **Self-Refine 论文**（Madaan 等 2023）；类比「草稿 → 批阅 → 修改」：学生交草稿、老师批注、学生按批注改，直到通过；
- 闭环靠**两个 prompt 驱动**：评估 prompt 扮「检查者」专门找问题，改进 prompt 按批注做定向修改。
```text
# 评估 prompt：给出检查维度 + PASS 出口
任务：{task}
当前输出：{current_output}
请评估以上输出：
1. 有没有事实错误或逻辑问题？
2. 有没有遗漏重要内容？
3. 表达是否清晰准确？
如果输出已经足够好，回复「PASS」；
否则指出具体问题并给出改进建议。
```
**🔥 评估 prompt 的两个关键设计（面试必答）**：
1. **明确检查维度**（事实、逻辑、完整性、表达）：不给方向，LLM 往往只说「输出看起来不错」，评估流于表面；
2. **「PASS」机制必须存在**：给 LLM 一个「够好了就停」的出口，否则它会为反思而反思、无限挑毛病，甚至把原本对的东西改错。
```text
# 改进 prompt：三个输入缺一不可
原始任务：{task}
当前输出：{current_output}
评估意见：{reflection}
请根据评估意见改进输出：
```
- ⚠️ 改进 prompt 必须**同时传入原始任务 + 原始输出 + 评估意见**：缺任务会改着改着偏离目标，缺原始输出不知道在什么基础上改，缺评估意见不知道改哪里；
- 两个 prompt 循环调用，直到回复 PASS 或超过最大轮次，外层就是一个普通的 for 循环。
### 两个粒度：步骤级 vs 任务级
| 维度 | 步骤级反思 | 任务级反思 |
|:---|:---|:---|
| 触发时机 | 每个工具调用/推理步骤后立即检查 | 整个任务执行完做一次整体评估 |
| 优点 | 错误早发现早纠正，不会层层放大 | 开销小（只多一次调用）；能从整体视角发现「各步单独都对但整体前后矛盾」的问题 |
| 代价 | 每步多一次 LLM 调用，10 步任务可能变 20 次 | 中途某步出大错到最后才发现，前期执行全浪费 |
| 适用场景 | 步骤间**强依赖**、前错后全错（如多步检索） | 步骤相对独立、整体质量更重要（如生成报告） |
### 多 Agent 互评：为什么「他人审视」优于「自我检查」
- 做法：设独立的 **Critic Agent** 审查执行 Agent 的输出 → 批注 → 执行 Agent 修改 → Critic 再确认；
- 为什么更好：同一模型生成时形成的「内部逻辑」在评估时会被沿用，对自己的错误不敏感、容易「自洽」；独立 Critic 没有包袱、唯一职责是找问题，视角更客观（类比自审代码 vs 同事 review）；
- 适用：质量要求极高的场景（代码生成后由测试 Agent 验证、报告由事实核查 Agent 交叉验证）；代价是多一个 Agent 的成本和复杂度，普通场景自我反思即可。
### 进阶：Reflexion、LATS、辩论式反思（面试加分项）
- **Reflexion**（Shinn 等 2023）：不止反思当前输出，还把「失败经验」存为**经验记忆**，塞进后续任务的上下文里参考，避免重蹈覆辙。类比：Self-Refine 是「写完当场改」，Reflexion 是「把错记在本子上，下次写前先翻笔记」。适合重复执行类似任务的场景（如代码生成 Agent 记住某类 bug 的成因）；
- **LATS**（Zhou 等 2024）：把**蒙特卡洛树搜索（MCTS）与反思结合**，同时探索多条路径，每条路径执行后评估反思，经验反馈给后续路径探索。成本最大，目前主要是学术研究场景，缺成熟生产级实现；
- **辩论式反思**：设「正方 Agent」提方案、「反方 Agent」专门挑毛病、正方再优化。对抗式反思比单方面审查更能暴露深层问题，用于商业决策分析、法律文本审查等高质量场景。
### 工程权衡：怎么用才合理？
- ✅ 值得开：输出质量要求高、错误代价大的关键节点（最终报告、重要决策推理）、任务复杂易遗漏细节的场景；
- ❌ 不值得开：简单直接的任务（格式转换、简单问答）、实时性要求高的场景（一次反思延迟可能 1s → 3s）；
- **🔥 防死循环是红线：必须硬性设最大轮次（通常 2~3 轮），绝不依赖 LLM 自己判断停止**——LLM 会陷入「为了改而改」的循环，每轮改动很小但实质没进步，硬性上限是唯一可靠的退出机制；
- 成本数字要有认知：每轮反思 = 1 次评估 + 1 次改进，**3 轮反思 = 额外 6 次 LLM 调用**。
## ⚠️ 面试常见踩雷点
1. **把反思说成「不满意就重新生成一次」**：最常见误区，没理解反思是有结构的闭环而非随机重试；
2. **评估 prompt 不给维度、不设 PASS**：导致评估流于表面或无限挑毛病；
3. **忽略步骤级/任务级的粒度取舍**：两者开销和适用场景完全不同；
4. **依赖 LLM 自己判断停止**：必须硬性设 2~3 轮上限防死循环。
