# Agent 面试题 20：Agent 为什么会出现路径震荡、重复调用和死循环？怎么检测和治理？
> 来源：https://xiaolinnote.com/ai/agent/20_loop_stability.html
## 🎯 核心考点一句话
考你能否分清「**一直在忙**」和「**任务在推进**」：动作重复 ≠ 死循环，**状态长时间没有向完成标准推进**才是无进展循环；最大步数只是兜底保险丝，不是根因治理。
## 💡 简要回答（面试可直接背）
- 成因：目标和停止条件模糊、工具失败只返回空结果、任务状态没随执行结果更新、多 Agent 职责边界不清形成 A→B→A 交接环；
- 检测：记录每步的 Agent/工具/标准化参数/结果摘要/状态差分，结合**动作指纹 + 输出相似度 + 状态变化 + 调用图成环**四个角度，再用步数、时间、Token、成本、交接次数做全局预算；
- 治理：先区分临时性错误（有界退避重试）和无进展循环（换参数 → 换工具 → Replan → Orchestrator 介入 → 人工接管）；预算耗尽或风险越界就停止自动执行，把已完成结果、卡点和可选方案交给人。
## 📝 详细解析
### 三个程度，不能混为一谈
| 现象 | 定义 | 判断要点 |
|:---|:---|:---|
| 重复调用 | 同一工具+近似参数多次出现 | 可能是分页拉取、限流有界重试，属合理行为 |
| 路径震荡 | 在几条路径间来回切换（搜索→总结→再搜索、A→B→A） | 看每次切换后状态有没有实质更新 |
| 死循环 | 系统缺少有效出口，预算耗尽前无法自停 | 需外部预算兜底 |
无进展循环的关键特征：新一轮**没有新证据、没有完成新子任务、没有缩小与成功标准的差距**。检测要同时看「做了什么」和「状态变了什么」。
### 四类成因（沿执行链排查）
1. **完成标准缺失**：「查一下合适的时间」没有定义返回几个时段、查不到怎么退出，Checker 只能让 Executor「再试一下」；
2. **工具反馈差**：超时/限流/参数错误/权限拒绝都包装成「调用失败」，模型不知道该重试、改参数还是换工具，最容易重复上一个动作；
3. **状态没写回**：工具成功了但没把已完成步骤和新证据写回状态，模型下一轮以为「还没做」；有副作用工具缺幂等键时重复调用风险更大；
4. **路由成环**：多 Agent 只有局部视角，互相把任务踢给对方；或 Planner 不改计划版本，Executor 一直执行过时步骤。
### 检测：四个角度 + 全局预算
1. **动作指纹**：子任务 + Agent 名 + 工具名 + 标准化参数取哈希（参数键顺序、多空格不应算新动作），近期窗口反复出现先打预警；
2. **结果与状态**：比较输出摘要的语义相似度、结构化工具比较关键字段；任务状态看已完成步骤是否增加、待办是否缩小、是否有新证据、阻塞原因是否变化；**动作相似+输出相似+状态没推进 = 足够证据**；
3. **路径调用图**：节点是 Agent/工具，边是调用/Handoff；A→B→A 成环后还要检查回到 A 时状态有无更新（审核→修改→再审可能是正常环）；
4. **全局预算**：最大步数、执行时间、Token、成本、单工具重试、Handoff 次数——是保险丝不是诊断；阈值按任务类型用离线轨迹回放校准，简单查询和深度研究不能共用一组数字。
### 治理三板斧
1. **读懂失败再重试**：工具返回结构化错误（错误码、类型、是否可重试、建议等待、可行下一步）；临时性错误预算内退避重试+随机抖动；参数/权限错误换参数或请用户授权，原样重试无意义；
2. **换路**：改参数要有实质差异；能力不匹配就换备选工具或降级路径；一个工具连续多任务失败时调度层开**熔断器**快速拒绝；
3. **Replan**：从最近检查点恢复，把原始目标、已完成结果、当前阻塞、已尝试路径交给 Planner 生成新剩余计划；**新计划要有新版本并把无效路径写入约束**，否则只是用更多 Token 重生成旧计划；
多 Agent Handoff 环由 Orchestrator 介入：读各 Agent 职责、已访问路径和全局状态，决定改派或暂停请用户补充信息。
### 事前预防（最省成本的治理）
- 每个子任务定义输入、预期输出、**完成标准和失败出口**（「找到可核验证据，指定来源无结果则返回缺失项」可验收，「查找有用信息」不可验收）；
- 状态更新成为执行协议：工具成功后在一个事务中记录结果标识、已完成步骤和外部影响；副作用工具用任务 ID+动作 ID 生成幂等键；
- 路由层限定职责边界：每个 Agent 写清接收条件、可交接对象、交接前必须附带的事实；主流程能用确定性状态机表达就由代码控制路由；
- 每步的输入/输出/错误/状态增量/路由决策/预算消耗写进 Trace；修改策略后把失败轨迹加入回归集，既验证能打断循环，也验证不误伤正常长任务。
## 🎯 面试总结
- 判断标准：任务状态长时间没向完成标准推进才是要治理的无进展循环，动作重复只是预警；
- 成因沿执行链排查：完成标准 → 工具错误反馈 → 状态写回 → 计划版本 → 交接图成环；
- 检测：动作指纹 + 输出相似度 + 状态差分 + 调用图，预算做最后止损，阈值按任务类型校准；
- 治理分级：有界重试 → 换参数/换工具/熔断 → Replan（带约束的新版本计划）→ 人工接管；到达边界要保留检查点、已完成结果和失败原因交给人，而不是只返回「超过最大步数」。
