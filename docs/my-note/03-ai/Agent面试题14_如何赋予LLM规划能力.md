# Agent 面试题 14：如何赋予 LLM 规划能力？
> 来源：https://xiaolinnote.com/ai/agent/14_planning.html
## 🎯 核心考点一句话
规划能力 = **把 LLM 隐式的推理过程显式化**，主流方案是层层递进的三种机制：**CoT（思维链）→ ToT（思维树）→ GoT（思维图）**，每一步都在解决前一步的局限；工程实践中最常用的规划模式是 **Plan-and-Execute**（先规划再执行，规划和执行分离）。
## 💡 简要回答（面试可直接背）
- **CoT（Chain of Thought）**：让 LLM 把推理步骤写出来，线性一步步推导到答案，实现成本最低（改个 prompt）；
- **ToT（Tree of Thoughts）**：同时探索多条推理路径，边探索边评估边剪枝，解决 CoT「走错方向就全错」的问题，但调用成本约为 CoT 的 3~5 倍；
- **GoT（Graph of Thoughts）**：图结构推理，不同路径的中间结论可以合并复用，适合更复杂任务，目前偏学术、生产环境极少落地；
- 工程上还有一种更贴近实践的模式 **Plan-and-Execute**：先让 LLM 生成完整计划，再逐步执行并动态重规划，常和 ReAct 搭配使用。
## 📝 详细解析
### 为什么需要规划能力？
- 普通问答模式下 LLM 接到问题直接「一口气」生成答案，中间没有推理过程；遇到需要多步推导的任务很容易翻车（3 步推导的逻辑题，直接给答案的出错概率远高于写出每步）；
- 根源是 Transformer 的 next-token 预测机制：推理链越长、隐式跳步越多，误差越容易在中间某步悄悄累积，最后给出**看起来很自信但实际错误**的答案；
- 规划能力要解决的就是：**把隐式推理显式化，不再「一步跳到答案」而是「一步一步推到答案」，每步有迹可循**。CoT、ToT、GoT 是这个方向上依次演进的三种方案。
### CoT：最简单的激活方式，加一句话就够了
- 核心思路：prompt 里加「请一步步思考」，LLM 把推理过程逐步写出来而非直接蹦答案；
- 为什么有效：LLM 输出是顺序生成的，**先写下来的推理步骤会进入上下文，成为后续 token 生成的依据**，帮助不跳步、不乱想（类比纸上演算 vs 心算）；
- 两种触发方式：
  1. **Zero-shot CoT**：prompt 末尾直接加「让我们一步步思考」，不需额外例子；
  2. **Few-shot CoT**：给几个带完整推理过程的示例让 LLM 模仿，效果通常更稳定；
- ⚠️ 局限：**只有一条推理路径**，一开始走错方向整条链就歪了，没有任何纠偏机制。
### ToT：从「一条链」到「一棵树」，解决走错方向的问题
- 核心改变：把「生成一条推理链」变成「同时探索多条推理路径，边探索边剪枝，选出最优路径」；
- 类比：CoT 像只想一个解法一路做到底；ToT 像先想三种解题思路、评估哪种最靠谱、选最好的深入、其余放弃；
- 执行流程三步（循环进行）：
  1. **生成多个候选思路**：同一问题给出 3 个不同的初步方向；
  2. **评估可行性**：用另一次 LLM 调用（或同一 LLM 带评估 prompt）给每个思路打分；
  3. **选优深入、剪掉差的**：只保留高分思路展开下一层，反复循环直到得出答案；
- ⚠️ 注意纠正常见误解：ToT **不是最后才选最优，而是「生成 → 评估 → 剪枝」边探索边剪枝的循环过程**，让 LLM 有「走错了还能回头」的能力；
- 代价：原来 CoT 一次生成搞定，ToT 需多次 LLM 调用（路径数 × 深度 × 每层评估）。典型设置（每层 3 条路径、搜 2~3 层）下**成本约为 CoT 的 3~5 倍**；极端场景（深搜、更多路径）可能 10 倍以上。
### GoT：从「树」到「图」，解决推理结果不能复用的问题
- ToT 是树形结构，**不同分支完全独立，中间结论无法互相借用**；GoT 把结构换成图，允许不同路径的中间结果合并、复用——一个推理节点可接收多个前置节点的输出作为输入；
- 例子：任务「分别研究竞品 A 和竞品 B，再做综合对比」。ToT 里两条路径独立得出结论，但「综合对比」需要同时用到两条路径的结论，树形结构很难自然表达（每个节点只有一个父节点）；GoT 的图结构让「研究 A 节点」和「研究 B 节点」的输出汇聚到「综合对比节点」，「多个中间结论合并输入」是一等公民；
- 现状：能建模的推理模式比 ToT 更丰富、更接近人类处理复杂任务的方式，但**落地复杂度高，目前主要是学术研究，生产环境极少真正用起来**。
### 三者的演进关系与工程取舍
| 机制 | 解决的问题 | 结构 | 成本 | 落地情况 |
|:---|:---|:---|:---|:---|
| CoT | 要不要把推理显式化 | 单条链 | 几乎零成本（改 prompt） | 所有任务标配 |
| ToT | 走错方向怎么纠偏 | 树（多路径+剪枝） | CoT 的 3~5 倍（极端 10 倍+） | 准确率要求高、任务复杂时考虑 |
| GoT | 不同路径中间结论能否复用 | 图（结论可合并） | 更高 | 学术阶段，生产极少落地 |
- 每一步都是针对上一步的局限改进：CoT 证明「写出过程能减少跳步出错」→ ToT 解决「单链走错无法纠偏」→ GoT 解决「树的分支间结论不能复用」。
### 🔥 工程里真正常用的规划模式：Plan-and-Execute
- 思路：面对复杂任务，**先让 LLM 制定完整执行计划（拆成若干步骤），再一步步执行，每完成一步检查进度、必要时调整后续计划**——「先写大纲再动笔」，而非拿到题目一口气往下写；
- 为什么需要：CoT 是「边想边做」、走到哪算哪、没有全局视角；多工具多环节的复杂任务没有整体规划，LLM 容易某步跑偏、后面全白费。**核心价值：先用一次 LLM 调用建立全局视角，再用后续调用逐步落地，规划和执行分两阶段**；
- 执行流程三步：
  1. **Planner（规划器）**：接收任务生成步骤清单（如「搜索资料 → 整理信息 → 撰写报告」）；
  2. **Executor（执行器）**：按清单逐步执行，每步可能涉及工具调用或 LLM 推理；
  3. **Re-planner（重规划器，容易被忽略的关键）**：每步完成后回顾进展，判断原计划是否仍适用，发现新信息或结果不符预期就动态调整后续步骤；
- **与 ReAct 的关系（高频追问）**：ReAct 是每步「思考 → 行动 → 观察」的即时决策循环，没有提前规划；Plan-and-Execute 是在其上加一层全局规划——**ReAct 负责每一步怎么执行，Plan-and-Execute 负责步骤的整体编排和动态调整**，两者不替代、常搭配使用；
- 工程好处：规划阶段用更强的模型（如 GPT-4）保证方向正确，执行阶段用更快更便宜的模型提效率，**成本和质量分别优化**；LangGraph 内置了该模式的支持。
## ⚠️ 面试常见踩雷点
1. **把 CoT 和规划能力画等号**：最常见误区。规划能力是个方向，CoT 只是最基础的实现手段；
2. **以为 ToT 是「最后选最好的链」**：不准确。ToT 是边探索边评估边剪枝的循环过程；
3. **说不清三者的演进逻辑**：必须讲清每一步在解决上一步的什么局限；
4. **忽略工程取舍**：只讲原理不讲成本。要能说出 ToT 典型成本是 CoT 的 3~5 倍、GoT 生产环境没有成熟落地。
## ✅ 答题 checklist
- [ ] 先讲动机：LLM 默认一口气生成答案、多步推理易跳步出错，规划 = 推理显式化；
- [ ] 讲清 CoT/ToT/GoT 演进逻辑：显式化 → 走错纠偏 → 结论复用；
- [ ] 给出工程取舍数字：CoT 零成本标配、ToT 3~5 倍成本、GoT 学术阶段；
- [ ] 补充 Plan-and-Execute：Planner/Executor/Re-planner 三角色、与 ReAct 的搭配关系、规划用强模型执行用便宜模型的成本优化。
