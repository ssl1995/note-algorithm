# Agent 面试题 13：在工程实践中，为什么有时候选择「手搓」Agent，而不是直接用成熟框架？
> 来源：https://xiaolinnote.com/ai/agent/13_handcode.html
## 🎯 核心考点一句话
框架和手搓不是非此即彼，核心是**想清楚各自边界**：框架胜在 POC 阶段的速度，但抽象层深、升级有 breaking change、通用性设计有隐性开销；手搓的核心价值是「**完全掌控**」——可观测、可裁剪、不受外部升级影响。生产环境最务实的答案是折中：**核心逻辑手写，周边工具借用框架**。
## 💡 简要回答（面试可直接背）
框架用起来快，但有三个实际痛点：
1. **抽象层太多**：调试时不知道哪步出了问题，stack trace 动辄四五十层，得一层层往下扒；
2. **版本升级有破坏性变更**：breaking change 让线上稳定性难保证；
3. **通用性设计产生隐性性能开销**：框架为兼容各种用法内置的逻辑（序列化、callback、日志），你的场景用不到但每次调用都在跑。
手搓代码完全在自己掌控之内：可观测性好、出问题好排查、性能优化空间全在自己手里。实际策略是**核心逻辑手写，边缘功能借用框架工具**。
## 📝 详细解析
### 框架的价值是真实的：省掉重复的样板工作
- 从零搭 Agent 要重复做一堆大同小异的事：定义工具格式、解析 LLM 返回的工具调用、维护对话历史、处理失败重试、接向量库检索……框架的价值就是把这些全部封装好；
- LangChain 里 `@tool` 装饰器注册工具、`AgentExecutor` 封装整个 ReAct loop，还内置 tracing、callback、记忆管理（注意：`AgentExecutor` 在新版已被废弃、官方推荐迁移 LangGraph——这恰好印证了框架升级痛点）；
- 早期上手快是真实优势：两周的工作缩短到两天，**POC 阶段框架几乎没有明显副作用**。
### 痛点随项目阶段逐渐浮现
- **探索期**：框架很爽，几十行搭起能用的 Agent，感受不到副作用；
- **第一个奇怪的 bug 出现后**：代码只有 50 行，stack trace 却有 40 层追到框架内部——不知道问题出在自己代码、框架某版本逻辑变化、还是 callback 触发时机。类比：老式车开引擎盖能看到哪根管漏油，现代豪华车只能去 4S 店扫诊断仪。**排查需要穿透你没写、也不完全懂的抽象层，是实实在在的认知负担**；
- **版本升级踩坑**：线上跑了几个月，某次依赖升级接口变了代码直接报错，要么回滚要么改十几处（LangChain 早期 breaking change 频繁，后采用 semver 有所改善，但教训让很多团队对框架依赖保持警惕）。**把核心业务建立在第三方框架上，线上稳定性就受外部不确定性影响**；
- **规模化后的隐性开销**：profile 后发现框架每次调用都在做你不需要的事——序列化中间结果、触发一堆 callback、记录详细日志。这些为通用性设计的逻辑高流量下累积成真实的延迟和费用浪费。
### 手搓的本质优势：完全掌控
1. **链路透明、可观测性好**：每行代码都知道在干什么，任意位置加日志、打断点、插监控，没有黑盒；线上出问题靠日志复现是最快的定位方式；
2. **精确裁剪、没有多余开销**：只写确实需要的逻辑，工具调用、历史维护、错误重试都按具体场景实现，没有为「兼容其他用法」存在的冗余，优化空间完全在自己手里；
3. **稳定可控、不受框架升级影响**：自己写的接口不会突然变，依赖只有底层 LLM SDK，生产环境可长期运行。
- 🔥 **Anthropic 官方 Agent 构建指南也建议**：不要一上来就用框架，先用最少的抽象把核心逻辑跑通——「框架的抽象层让你离底层更远，出了问题调试成本比省下的开发时间还高」；
- 类比：框架是「租房」（装修好直接住，但结构改不了、房东随时调政策），手搓是「自建」（建得慢，但所有结构都熟悉、改什么都能改）。
### 同一个需求对比：框架写 vs 手搓写
用 LangChain 实现带工具调用的 Agent loop：
```python
from langchain.agents import AgentExecutor, create_openai_tools_agent
# 框架封装好了 Agent loop，一行搞定
agent = create_openai_tools_agent(llm, tools, prompt)
executor = AgentExecutor(agent=agent, tools=tools)
# 整个 ReAct 循环、工具调用、消息维护，全在 executor 内部
result = executor.invoke({"input": "帮我查一下今天的天气"})
```
- 确实简洁，三四行跑起来；但想知道「LLM 返回了什么、工具怎么被选中的、消息列表什么顺序」，得去读 `AgentExecutor` 源码，内部调用链可能有十几层。
手搓同样的功能，代码量多一些，但每一步都在眼前：
```python
messages = [{"role": "system", "content": system_prompt}]
messages.append({"role": "user", "content": user_input})
for i in range(max_turns):  # 手动控制最大轮次
    # 调用 LLM，拿到响应
    response = client.chat.completions.create(
        model="gpt-4", messages=messages, tools=tool_schemas
    )
    msg = response.choices[0].message
    messages.append(msg)  # 把 LLM 响应加入对话历史
    # 如果没有工具调用，说明 LLM 认为任务完成了
    if not msg.tool_calls:
        break
    # 有工具调用，逐个执行并把结果写回消息列表
    for tc in msg.tool_calls:
        result = execute_tool(tc.function.name, tc.function.arguments)
        messages.append({
            "role": "tool",
            "tool_call_id": tc.id,
            "content": result
        })
        # 这里可以随意加日志、监控、重试逻辑
        logger.info(f"工具 {tc.function.name} 返回: {result}")
```
- 手搓版里消息怎么拼、工具怎么选、循环何时退出，每个细节都摆在明面上，出问题看这二十行就够——**这就是「完全掌控」的具体含义**。
### 什么时候用框架，什么时候手搓？
| 场景 | 选择 |
|:---|:---|
| POC 阶段快速验证 idea，目标是跑通 | 框架 |
| 团队刚接触 Agent 开发，少踩基础坑 | 框架 |
| 周边工具依赖框架生态（文档解析、向量检索），核心逻辑不复杂 | 框架 |
| 准备上生产，稳定性是核心关切 | 手搓 |
| 流量上来，性能和成本敏感 | 手搓 |
| 业务逻辑高度定制，和框架通用设计偏差大 | 手搓 |
| 需要高可观测性，链路随时监控回溯 | 手搓 |
### 🔥 折中方案：核心手写，周边借用（最常见最务实）
- **手写「心脏」**：工具调用循环、对话历史管理、错误处理和重试、任务状态维护——直接决定系统行为，必须百分百理解和掌控；
- **借用「周边」**：LangSmith 的 tracing、LlamaIndex 的文档解析、向量库的 Python 客户端——工具性功能，出问题一眼能看出，不会带来黑盒困境；
- 类比盖房子：核心结构、承重墙、房间布局自己设计；门锁、插座、水龙头买现成的。
### 工程实践的清醒视角
- 手搓不是「比框架更好」，而是「在特定阶段有特定价值」；
- 典型演进轨迹：**框架快速跑通验证方向 → 第一批线上问题后把难排查的关键部分换成手写 → 流量上来后性能敏感的核心逻辑全部手写 → 框架只保留做得好的周边工具**。既享受了早期的速度，又在生产阶段拿回掌控权；
- 判断信号：能清楚说出「框架在这里替我做了什么、这个方法内部发生了什么」就有掌控感；只是调了一个方法但完全不知道里面发生了什么，就是不透明的黑盒——**框架本身不是问题，「不理解就依赖」才是**。
## ⚠️ 面试常见踩雷点
1. **只说「框架好用、效率高」**：没想清楚框架在什么阶段开始出问题、为什么手搓能解决；
2. **一开口就否定框架**：框架在 POC 阶段的价值是真实的，不要走极端；
3. **痛点泛泛而谈**：「框架有缺点」没有说服力，要说具体——抽象层深排查难、breaking change、隐性性能开销这三个生产中最常见；
4. **忽略折中方案**：核心手写 + 周边借用才是实际项目最常见的选择，面试官通常很认可这个答法。
## ✅ 答题 checklist
- [ ] 先肯定框架价值：POC 阶段省时省力；
- [ ] 说清三个具体痛点：抽象层排查难、版本 breaking change、通用性隐性开销；
- [ ] 点明手搓核心价值「完全掌控」：可观测、稳定、性能可裁剪；
- [ ] 给出折中方案：核心逻辑手写，周边工具性功能借用框架；
- [ ] 记住金句：框架不是问题，「不理解就依赖」才是。
