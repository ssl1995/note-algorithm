# Agent 面试题 10：什么是 Multi-Agent？
> 来源：https://xiaolinnote.com/ai/agent/10_multiagent.html
## 🎯 核心考点一句话
Multi-Agent 是多个各有分工的 Agent 协作完成任务，其存在的根本驱动力是单个 Agent 的两个硬限制：**context window 的结构性上限**和**单点专业度不足**，再加上**并行执行**带来的效率提升。
## 💡 简要回答（面试可直接背）
- Multi-Agent（多智能体系统）就是多个 Agent 协作完成任务，每个 Agent 各有分工：有的负责搜索、有的负责写代码、有的负责做评审；
- 单个 Agent 有两个硬限制：一是 **context 窗口大小**，复杂任务信息量一多就撑爆、开始「遗忘」；二是**单点能力**，什么都让一个 Agent 做，每件事都是泛才；
- Multi-Agent 通过**专业分工**和**并行执行**处理更复杂、更长流程的任务——这是实际项目里选择多智能体方案的核心原因。
## 📝 详细解析
### 单个 Agent 的两个硬限制
**限制一：context window 的结构性上限**
- LLM 处理任务的方式是把当前能看到的所有内容（指令、推理过程、工具返回、历史对话）全部摆在 context window 这张「工作台」上一起处理；
- 以「写一份 AI 行业竞品分析报告」为例：搜十几家竞品、每家几百字，加上来回确认的对话历史和中间推理，还没写结论工作台就快满了；
- context window（常见 12.8 万~100 万 token）塞满后早期内容「掉落」——三十分钟前确认的方案、第一批搜集的资料悄悄消失，Agent 开始「遗忘」。这是结构性上限，不是优化能绕过去的。
**限制二：专业度问题（更深层）**
- 让一个 Agent 既搜信息、又写代码、又做测试、又写文档，精力分散、每件事都不够专注、互相干扰——像一个人同时担任产品经理、程序员、测试、文档工程师；
- 且某个环节出问题整条链路卡住，没有隔离性，排查痛苦。
### Multi-Agent 核心思路：团队作战代替单打独斗
把任务按职能拆开，每个 Agent 只负责一件事，做完把结果传给下一个。
**三种协作模式**：
1. **顺序流水线（Sequential Pipeline）**：A 做完交给 B、B 做完交给 C，像工厂流水线依次处理；
2. **并行扇出（Fan-out）**：调度者把多个独立子任务同时分发给不同 Worker Agent 并行执行，最后收集汇总；
3. **辩论/评审模式（Debate/Review）**：多个 Agent 对同一问题各给方案，由裁判 Agent 或互相评审筛选最优解——适合代码评审、方案选型等高质量决策场景。
类比公司部门协作：产品经理梳理需求、开发写代码、测试验收，每个人专注职责、信息传递清晰、出问题好定位责任。
### 实例对比：开发一个爬虫工具
- **不用 Multi-Agent**：一个 Agent 同时想需求、代码结构、测试策略，context 塞满、思路混乱，哪块都做不好，任何一步失误从头来；
- **用 Multi-Agent**：
  - 「需求分析师」Agent 只把需求转成清晰功能列表，输出后退出，工作台干净；
  - 「程序员」Agent 拿功能列表专注写代码，context 里只有代码相关信息；
  - 「测试工程师」Agent 拿代码专注写测试用例；
- 需求分析结束后，程序员和测试可以**并行工作**（测试框架搭建不用等代码写完）——Orchestrator 识别出无依赖关系的子任务同时派出去，结果回来统一整合；
- 并行不只是提速，还有隐藏好处：**每个 Worker 的 context 完全隔离**，互不干扰，各自在干净环境里专注，输出质量更高。
### 业界框架
- **CrewAI**（上层更易用）、**LangGraph**（底层更灵活）：已封装好 Agent 间通信协议、任务调度、结果汇总，开发者只需定义角色和工具；
- ⚠️ **微软 2025 年推出 Microsoft Agent Framework（MAF）**：把原 Semantic Kernel（企业级）和 AutoGen（多 Agent 编排）合并为面向生产的统一 SDK；AutoGen 仓库转为研究/原型项目，社区 fork 出 AG2 保持兼容。微软技术栈生产场景优先 MAF。
### 组织方式：中心化 vs 去中心化
- **中心化**：一个统一调度者分配任务、收集结果；
- **去中心化**：Agent 之间自行协商、直接通信；
- 工程上用得更多的是**中心化**：调度逻辑清晰、责任归属明确、排查问题容易。
### Multi-Agent 的价值总结
- **分工突破专业度上限**：每个 Agent 的 prompt、工具、context 都围绕单一职责设计，比「全能选手」在每个环节都做得更好；
- **隔离降低干扰**：子任务各自独立的 context，互不污染，出错影响面也被隔离在单个 Worker 内；
- **并行提升吞吐**：无依赖的子任务同时执行，整体耗时从串行叠加变成最慢那个子任务的耗时。
## ⚠️ 面试常见踩雷点
1. **泛泛而谈「多个 AI 一起工作效率更高」**：说不出具体技术驱动因素——必须点明 context window 硬上限（结构性限制）和专业度问题（身兼数职每件事都不专注）；
2. **把「处理不过来」挂在嘴上说不清根因**：「任务复杂容易出错」太模糊，面试官要的是 context 上限 + 专业分工 + 并行能力这三个具体点；
3. **忽略 context 隔离这个隐藏收益**：每个 Worker 只装自己任务的信息，环境干净、质量更高。
