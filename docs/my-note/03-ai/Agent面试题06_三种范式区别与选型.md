# Agent 面试题 06：ReAct、Plan-and-Execute、Reflection 三种范式有什么核心区别？实际项目中该如何选型？
> 来源：https://xiaolinnote.com/ai/agent/6_three_patterns.html
## 🎯 核心考点一句话
三者解决的是**不同层次的问题**，不是谁比谁好：**ReAct 解决单步灵活性，Plan-and-Execute 解决长任务跑偏，Reflection 解决输出质量不达标**；其中 Reflection 不是独立流程，是叠加在前两者之上的「检查 buff」。选型看三维度：**任务复杂度、流程确定性、输出质量要求**。
## 💡 简要回答（面试可直接背）
- 核心区别在于「决策和执行的关系」：
- **ReAct** 边想边干、走一步看一步，单步迭代实时调整，灵活度最高；
- **Plan-and-Execute** 先想全再干，先定完整计划再分步执行，适合长流程复杂任务，不容易跑偏；
- **Reflection** 不是独立完整流程，是给前两者加的**「检查修正 buff」**，专门提升输出质量；
- 选型口诀：**任务简单用 ReAct，流程长且复杂用 Plan-and-Execute，输出要求高再叠加 Reflection，别过度工程化、够用就好**。
## 📝 详细解析
### 先分清两个概念：设计范式 vs 推理模式
- **设计范式**：搭 Agent 的「顶层做事流程框架」，定的是整个系统从头到尾按什么大逻辑跑（类比公司的管理制度）；
- **推理模式**：Agent 每一步干活时「脑子里具体怎么思考」，是底层的思考逻辑（类比员工的干活方法）；
- 两者一一对应：设计范式是制度，推理模式是方法。
### 一、基础款：ReAct 单步迭代范式
- 本质：**「思考 → 行动 → 观察 → 再思考」循环**，走一步看一步，每步行动完全基于上一步结果实时调整，**没有提前定死的完整计划**；
- 与另两者的核心区别：
  - vs Plan-and-Execute：没有「提前做完整规划」环节，**规划和执行混在一起**；
  - vs Reflection：循环里**没有专门的自我检查环节**，只有行动后的结果观察，不会停下来复盘；
- 优势：实现简单、灵活度高、逻辑透明、出问题好排查，新手入门零门槛；
- 短板：长流程多步骤复杂任务**容易跑偏、忘了最初目标**，也可能陷入无效循环；
- 适用：流程不固定、复杂度适中的任务（日常信息搜索、简单问答助手、客服机器人），**新手入门首选**。
### 二、复杂任务款：Plan-and-Execute 规划执行范式
- 一句话讲透与 ReAct 的区别：**ReAct 边想边干，Plan-and-Execute 先把完整计划定好再按计划一步步干**；
- 核心做法：把「规划推理」和「执行推理」**完全解耦**——专门一个 LLM 做规划（把大目标拆成执行清单），另一个 LLM（或模块）按清单执行，执行完统一汇总；
- 🔥 隐藏优势——**「强模型规划、弱模型执行」混合策略**：规划对推理能力要求高，用 GPT-4 / Claude 等强模型保证拆分质量；执行阶段每步任务已很具体，用便宜小模型（GPT-4o-mini 或开源 7B）足够。**实际项目可降低 70%~90% 总成本而质量几乎不受影响**——规划只调一次花费有限，执行调很多次每次用便宜模型。ReAct 每步都是同一模型又推理又执行，无法做这种差异化分配；
- 优势：整体结构清晰、执行链路可控、长流程任务不易跑偏、**方便做并行优化**（识别无依赖步骤并行执行，整体耗时明显降低）；工程经验上复杂多步任务完成准确率通常高于 ReAct（全局计划兜底）；
- 代价：灵活度不如 ReAct（计划外情况易卡住）、实现更复杂（需分别维护规划和执行模块）、token 消耗增加；
- 适用：流程长、复杂度高的任务（竞品分析报告、全流程项目开发、多维度行业调研）。
### 三、质量增强款：Reflection 反思迭代范式
- 🔥 最关键的定位：**Reflection 不是一套独立完整流程，而是叠加在 ReAct / Plan-and-Execute 之上的增强机制**，不改变原本做事流程，只加一层「自我检查、自我修正」；
- 核心循环：在原范式基础上加**「生成 → 评估 → 改进」闭环**——设独立检查环节判断输出达不达标，不达标就重试或调整策略；
- 与前两者最本质的区别：前两者核心是「把事做完」，**Reflection 核心是「把事做好」**，专门解决输出质量不达标、事实错误、逻辑漏洞；
- 优势：输出质量明显提升，幻觉、逻辑错误、细节遗漏减少，严谨性要求高的场景效果尤其明显；
- 代价：至少多一次 LLM 调用，**token 和延迟线性增加**；没有轮次限制容易陷入「为了改而改」的死循环，**一般设最多反思 2~3 轮**；
- 适用：输出质量要求极高、不能出错的场景（生产环境代码、正式商业报告、法律文书）。
### 进阶机制一：动态 Replan
- 解决 Plan-and-Execute 的核心痛点：**计划定死了，中途遇到意外怎么办**（如规划五步写竞品报告，执行到第三步发现某竞品已被收购，原分析框架失效）；
- 做法：每步执行完，把当前结果和剩余计划交给规划模块，判断「原计划还合理吗」，需要就生成新的剩余步骤计划替换；
- 保留了「先规划再执行」的结构优势，又不会因计划僵硬翻车；代价是每步多一次「重新评估计划」的 LLM 调用。
### 进阶机制二：Reflexion
- 把 Reflection 的「自我反思」推到更深层：普通 Reflection 是「做完检查、发现问题重做」；**Reflexion 会把每次失败原因总结成「经验教训」存进记忆，下次遇到类似任务作为上下文传给 LLM，避免重蹈覆辙**——类比「错题本」；
- 🔥 效果数据：**HumanEval 代码生成基准上，Reflexion 把 GPT-4 的 pass@1 从 80% 提升到 91%**（+10 个百分点），同样的基座模型仅加「反思 + 记住教训」机制；
- 代码生成天然适合 Reflexion：代码可运行可测试，执行结果就是最直接的反馈信号，测试不过就分析「API 参数顺序搞反了」「边界条件没处理」等具体教训，带着教训重试；
- 这种 **「verbal reinforcement learning」（语言强化学习）** 思路让 Agent 不需要梯度更新就能从错误中学习，适合推理阶段提升质量。
### 🔥 token 消耗对比（选型必须考虑的现实因素）
假设一个需 5 步工具调用的任务，每步推理和工具结果平均 2000 token：
| 范式 | 消耗模式 | 估算总消耗 |
|:---|:---|:---|
| ReAct | 每次调 LLM 带完整历史，输入 2000+4000+6000+8000+10000 递增 | ≈ 30000 token，随步骤线性增长 |
| Plan-and-Execute | 规划约 3000 + 执行每步约 1500（只带当前指令和前面结果摘要）×5 + 汇总约 4000 | ≈ 14500 token，比 ReAct 低一半多 |
| + Reflection | 每个需反思的节点至少多一次 LLM 调用（评估 + 不达标重做） | 在基础范式上增加 30%~100%，取决于反思轮次和严格程度 |
- 再叠加「强模型规划、弱模型执行」策略，token 数量差不多但实际花费能再降 70% 以上；
- 实践建议：**先用 ReAct 快速验证效果，跑通后再根据 token 消耗和延迟的实际数据决定是否切换或叠加**，不要一上来就选最复杂的方案。
### 选型指南
- 任务不复杂、流程不固定、需实时调整 → **ReAct**，够用就好；
- 任务很长、容易跑偏、需要整体结构清晰 → **Plan-and-Execute**；
- 执行中常遇意外需调整计划 → 加**动态 Replan**；
- 输出要求高、不能出错 → 叠加 **Reflection** 自我检查；
- 需跨任务积累经验、避免重复犯错 → 用 **Reflexion** 沉淀失败教训；
- 🔥 生产常见混合用法（三层嵌套）：**规划阶段用 Plan-and-Execute 定全局计划 → 每步执行用 ReAct 循环（单步也可能需多轮工具调用）→ 最后对整体输出做一次 Reflection 质量检查**。LangGraph 等框架里实现很自然，很多生产级 Agent 系统就是这么搭的；
- ⚠️ 最容易踩的坑：把所有范式全堆在一起（规划+反思+Replan+经验积累），系统又复杂又慢还容易出奇怪 bug。**工程开发永远是「够用就好」，先把 ReAct 玩明白再按需往上加**。
## ⚠️ 面试常见踩雷点
1. **说不清 Reflection 的定位**：它不是独立流程，是叠加在 ReAct / Plan-and-Execute 上的「质量增强 buff」，本身不能单独成立——这一点最多人搞错；
2. **只背概念说不出落地区别**：三者解决的是不同层次的问题（单步灵活性 / 长任务跑偏 / 输出质量），不是并列互斥的三种方案；
3. **过度工程化**：学了范式就全堆上去，忽略「够用就好、先跑起来再优化」的工程原则。
## ✅ 答题 checklist
- [ ] 先说清 Reflection 的定位：叠加增强机制，不是独立流程；
- [ ] 按维度对比三者：ReAct 灵活但长任务易跑偏；Plan-and-Execute 结构清晰但灵活度不足；Reflection 提质量但增 token 和延迟；
- [ ] 给出选型口诀：简单任务 ReAct、长流程 Plan-and-Execute、高质量要求加 Reflection，顺带一句「别过度工程化」；
- [ ] 加分项：动态 Replan 解决「计划太僵硬」；Reflexion「错题本」机制 + HumanEval 80%→91%；token 消耗对比数据；强模型规划弱模型执行降本 70%~90%；生产三层嵌套混合架构。
